# 1. Problem Overview

The objective of P2 is to generate valid arithmetic equations using a given list of integers.

The implementation must:

- Use every input integer exactly once.
- Preserve the original order of the input integers.
- Generate arithmetic expressions using `+`, `-`, `*`, and `/`.
- Divide the input into two non-empty contiguous portions.
- Ensure that both sides of the equation evaluate to the same integer.
- Prevent division by zero and inexact division, including in intermediate subexpressions.
- Generate canonical arithmetic expressions with correct operator precedence and parentheses.

The implementation is divided into individual units, followed by the public predicates for generating and counting equations.

# 2. Global Implementation Constraints

The following constraints apply to every proposed implementation prompt.

## 2.1 Language and Environment

- Target language: SWI-Prolog 9.x.
- Use only assignment-permitted libraries: `lists`, `apply`, `yall`, and `aggregate`.
- Follow the guidelines in `skills/prolog-dev/SKILL.md`.

## 2.2 Arithmetic Constraints

- Supported operators: `+`, `-`, `*`, `/`.
- Every input integer must be used exactly once.
- Original input ordering must be preserved.
- Unary minus and number concatenation are not permitted.
- Division is allowed only when the divisor is nonzero.
- Every division must produce an exact integer result.
- These restrictions apply to all intermediate subexpressions.

## 2.3 Expression Formatting Constraints

- Return SWI-Prolog strings, not atoms or character lists.
- Expressions must contain no unnecessary spaces.
- Use standard operator precedence:
  - `*` and `/` have higher precedence than `+` and `-`.
- All operators are left-associative.
- Parenthesize a left operand when its top-level precedence is lower than its parent's.
- Parenthesize a right operand when its top-level precedence is equal to or lower than its parent's.
- Numbers must never be parenthesized.
- Preserve the exact structure and evaluation order of expression trees.

## 2.4 Programming Constraints

- Do not use `assert/1` or `retract/1`.
- Do not use global variables.
- Do not parse generated strings back into Prolog terms for evaluation.
- Do not use initialization directives.
- Do not include top-level printing.
- The solution source must contain predicate definitions only.

**Objective:** Implement a predicate that recursively evaluates an arithmetic expression tree.

**Proposed Prompt:**

Choose a descriptive predicate name and document the expression-tree representation.

Require division to have a nonzero divisor and an exact integer result at every division node, including nested nodes.

Do not parse formatted strings or use global state. Use only SWI-Prolog 9.x and the allowed libraries.

Return the predicate and a short explanation; do not implement expression generation, formatting, equation generation, or tests in this response.

### P2-02 — One-Span Arithmetic Expression Generator

**Objective:** Generate all possible binary expression trees from a consecutive input list.

**Proposed Prompt:**

Using the attached assignment specification and Prolog skill, implement only one predicate that nondeterministically constructs possible binary expression trees from one nonempty, consecutive input list of nonnegative integers.

Each integer must occur once in its original order.

Include all binary tree shapes and operators `+`, `-`, `*`, `/`, without unary minus or concatenation.

Assume a separately implemented evaluator will reject invalid divisions; do not implement the evaluator, string formatting, whole equations, public APIs, or tests.

Respect the assignment's library and side-effect restrictions.

Return this one predicate with a concise rationale.

### P2-03 — Split Input at the Equals Sign

**Objective:** Split the input list into two non-empty contiguous portions.

**Proposed Prompt:**

Using the attached assignment and Prolog skill, implement only one helper predicate that nondeterministically splits a list into a nonempty left prefix and a nonempty right suffix, preserving order and using every element.

Lists with fewer than two integers must fail cleanly, without errors or looping.

Do not generate expressions, compute arithmetic, build strings, or implement public predicates.

Return just the helper and a brief explanation, using only assignment-permitted facilities.

## Stage 3 — Public Equation Generation

### P2-05 — `generate_equation/2`

**Objective:** Generate one valid arithmetic equation.

**Proposed Prompt:**

Using the attached assignment and Prolog skill, implement only `generate_equation(List, Equation)`.

Assume existing helpers can split the input into two nonempty consecutive parts, generate expression trees for each part, evaluate those trees with exact-division checks, and render each tree canonically.

Enumerate one valid equality at a time, with equal integer values on both sides.

Return `Equation` as a space-free SWI-Prolog string.

If there is no valid equation, particularly for zero- or one-element input, fail cleanly rather than error or loop.

Do not reimplement helpers, `all_equations/2`, `count_equations/2`, or tests.

Return only this predicate and a brief explanation.

### P2-06 — `all_equations/2`

**Objective:** Generate all distinct valid equations.

**Proposed Prompt:**

Using the attached assignment and Prolog skill, implement only `all_equations(List, Equations)`, assuming `generate_equation/2` already exists.

Collect every generated equation, remove duplicate strings, and sort the results using `sort/2` (the standard term order).

Return `[]` for any list with no valid equation, including empty and singleton lists.

Do not change `generate_equation/2`, implement `count_equations/2`, or create tests.

Use no mutation or global variables.

Return this one predicate and a short explanation.

### P2-07 — `count_equations/2`

**Objective:** Count the number of distinct valid equations.

**Proposed Prompt:**

Using the attached assignment and Prolog skill, implement only `count_equations(List, N)` assuming `all_equations/2` already exists.

Unify `N` with the number of distinct, sorted valid equations for `List`.

It must be zero when there are no equations.

Do not duplicate the equation-search logic or implement any other predicate.

Return only this definition and a brief explanation.
