## Problem constraints applicable to every proposed prompt

The target is SWI-Prolog 9.x. Use each input integer exactly once, preserving original order, with one equals sign and operators `+`, `-`, `*`, `/`. Divide only when exact and divisor nonzero, including for all subexpressions. Do not permit unary minus or concatenation. Produce SWI-Prolog strings, not atoms or character lists. Render each expression tree uniquely according to standard precedence (`*` and `/` above `+` and `-`) and left associativity: parenthesize a left operand when its top-level precedence is lower than its parent's; parenthesize a right operand when its top-level precedence is equal or lower; never parenthesize a number. Do not use `assert`, `retract`, global variables, or parse a generated string back into a term for evaluation. Only the libraries `lists`, `apply`, `yall`, `aggregate` are permitted. Solution source must contain definitions only, with no initialization directive or top-level printing.

The prompts below are **proposed review/decomposition prompts**, not claims about what was previously sent or how the program was developed.

## Proposed Prompt P2-01 — Numeric expression evaluator

Using the attached CS F301 Assignment 2 specification and `skills/prolog-dev/SKILL.md`, implement **only one Prolog predicate** that recursively evaluates an arithmetic expression tree made of integer leaves and binary operations `+`, `-`, `*`, `/`. Choose a descriptive predicate name and document the expression-tree representation. Require division to have a nonzero divisor and an exact integer result at **every** division node, including nested nodes. Do not parse formatted strings or use global state. Use only SWI-Prolog 9.x and the allowed libraries. Return the predicate and a short explanation; do not implement expression generation, formatting, equation generation, or tests in this response.

## Proposed Prompt P2-02 — One-span arithmetic expression generator

Using the attached assignment specification and Prolog skill, implement **only one predicate** that nondeterministically constructs possible binary expression trees from one nonempty, consecutive input list of nonnegative integers. Each integer must occur once in its original order. Include all binary tree shapes and operators `+`, `-`, `*`, `/`, without unary minus or concatenation. Assume a separately implemented evaluator will reject invalid divisions; do not implement the evaluator, string formatting, whole equations, public APIs, or tests. Respect the assignment's library and side-effect restrictions. Return this one predicate with a concise rationale.

## Proposed Prompt P2-03 — Split input at the equals sign

Using the attached assignment and Prolog skill, implement **only one helper predicate** that nondeterministically splits a list into a nonempty left prefix and a nonempty right suffix, preserving order and using every element. Lists with fewer than two integers must fail cleanly, without errors or looping. Do not generate expressions, compute arithmetic, build strings, or implement public predicates. Return just the helper and a brief explanation, using only assignment-permitted facilities.

## Proposed Prompt P2-04 — Canonical expression renderer

Using the attached assignment and Prolog skill, implement **only one predicate** to render an existing arithmetic expression tree into its canonical, space-free SWI-Prolog **string** form. The expression tree representation is described by the existing expression-tree generator. Apply the precise parenthesis rules: left child parenthesized only when lower precedence than parent; right child when equal or lower; numbers never parenthesized; `*` and `/` bind more tightly than `+` and `-`; all operators are left-associative. Distinguish tree shapes such as `1+(2+3)` from `1+2+3` and `8/(4*2)` from `8/4*2`. Do not evaluate strings, generate expression trees, implement public equations, or create tests. Return this single predicate and a short explanation.

## Proposed Prompt P2-05 — `generate_equation/2`

Using the attached assignment and Prolog skill, implement **only** `generate_equation(List, Equation)`. Assume existing helpers can split the input into two nonempty consecutive parts, generate expression trees for each part, evaluate those trees with exact-division checks, and render each tree canonically. Enumerate one valid equality at a time, with equal integer values on both sides. Return `Equation` as a space-free SWI-Prolog string. If there is no valid equation, particularly for zero- or one-element input, fail cleanly rather than error or loop. Do not reimplement helpers, `all_equations/2`, `count_equations/2`, or tests. Return only this predicate and a brief explanation.

## Proposed Prompt P2-06 — `all_equations/2`

Using the attached assignment and Prolog skill, implement **only** `all_equations(List, Equations)`, assuming `generate_equation/2` already exists. Collect every generated equation, remove duplicate strings, and sort the results using `sort/2` (the standard term order). Return `[]` for any list with no valid equation, including empty and singleton lists. Do not change `generate_equation/2`, implement `count_equations/2`, or create tests. Use no mutation or global variables. Return this one predicate and a short explanation.

## Proposed Prompt P2-07 — `count_equations/2`

Using the attached assignment and Prolog skill, implement **only** `count_equations(List, N)` assuming `all_equations/2` already exists. Unify `N` with the number of distinct, sorted valid equations for `List`. It must be zero when there are no equations. Do not duplicate the equation-search logic or implement any other predicate. Return only this definition and a brief explanation.
